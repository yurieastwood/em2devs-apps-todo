## WEIRD / NON-COMPLIANT Cases

### A. OpenAPI contract is severely out of sync

The contract (`docs/contracts/openapi.yaml`) only documents **Tasks** and **Profile** endpoints. **Missing ~20+ endpoints** that exist in code:

- All Quest endpoints (7)
- All Epic endpoints (7)
- All RecurringTask endpoints (7)
- All Auth endpoints (3)

This means any consumer generating a client from the OpenAPI spec gets a fraction of the actual API.

### B. Persistence gap — 4 of 5 repositories are InMemory only

| Repository                  | Backing Store        |
|-----------------------------|----------------------|
| `ITaskRepository`           | PostgreSQL (real)    |
| `IQuestRepository`          | **InMemory only**    |
| `IEpicRepository`           | **InMemory only**    |
| `IRecurringTaskRepository`  | **InMemory only**    |
| `IPlayerProfileRepository`  | **InMemory only**    |

Quests, Epics, Recurring Tasks, and Player Profiles **vanish on restart**. The ROADMAP says "Data persists across restarts" is a done exit criterion, but that's only true for tasks.

### C. Domain entities with no pipeline (dead code)

These entities exist in `Domain/` but have **no** repository, command, query, or API endpoint:

- `DailyBrief`, `EnergyCheckIn`, `Notification`, `CapacitySnapshot`, `EstimationRecord`
- `Guild`, `Season`, `SeasonalQuestLine`, `Title`, `TitleInventory`, `SkillTree`, `AccountabilityPartnership`

They're speculative domain modelling — built ahead of any feature slice.

### D. `@done` tag used inconsistently

Some scenarios are tagged `@done` when only the **domain value object** exists (Guilds, Seasons), while others are tagged `@done` only when there's a full vertical slice (Tasks, Quests). There's no documented definition of what `@done` means — "domain model exists"? "API works"? "Frontend works"? "Tests pass"?

---

## Recommendations

1. **Define what `@done` means** — e.g., "the scenario is exercisable through the API and covered by at least one test." Then re-tag the ~19 phantom scenarios to `@wip` or `@todo`.
2. **Bring the OpenAPI contract up to date** — add Quest, Epic, RecurringTask, and Auth schemas. Contract-first is only valuable if the contract is the truth.
3. **Promote InMemory repos to PostgreSQL** — Quests and Epics are core to daily use; losing them on restart breaks the MVP promise.
4. **Delete or fence speculative domain types** — `DailyBrief`, `EnergyCheckIn`, etc. add cognitive load with no payoff. Move them to a `_future/` namespace or remove until a feature slice needs them.
5. **Add an acceptance test project** — 341 scenarios with zero executable step definitions means the BDD specs are aspirational documentation, not living tests.
